# Design Rules

## Portfolio UI Style
The portfolio should feel like a premium engineering portfolio: technical, modern, minimal, and confidence-driven.

### Visual Principles
- Keep the dark, black-and-white aesthetic
- Use subtle borders, soft contrast, and generous whitespace
- Favor clarity and professionalism over decorative effects
- Keep visual language consistent with the original template

### Color System
- Primary background: dark neutral, consistent with the template
- Card surface: dark translucent panels with subtle borders
- Primary text: white
- Secondary text: muted white with reduced opacity
- Highlight state: white borders or bright contrast for emphasis

## Case Study Page Structure
Case-study pages should follow a consistent content hierarchy and feel like polished engineering stories.

### Recommended Structure
1. Hero section
   - Large project title
   - Short subtitle
   - Compact summary
   - Technology badges
   - Large visual placeholder or media area

2. Project story section
   - One short narrative intro
   - Compact journey timeline or story block

3. Architecture section
   - One strong visual placeholder
   - One short supporting paragraph

4. Engineering highlights section
   - Three concise cards focused on key system capabilities

5. Hardware section
   - Clean grid or table of key components

6. Simulation to real-world section
   - A visual comparison block with a short supporting line

7. Monitoring and safety section
   - Feature cards or short list blocks

8. Results section
   - Outcome-focused achievement cards

9. Final tech stack section
   - Badges only

## Spacing Rules
- Preserve the existing container structure, rows, and column system
- Use generous spacing between sections to keep the page airy
- Avoid dense paragraph blocks
- Keep cards visually separated with subtle borders and padding
- Use Bootstrap spacing patterns when practical

## Typography Rules
- Headings should feel confident and technical
- Keep text concise and high-signal
- Use short paragraphs and compact lists
- Avoid overly long prose blocks
- Maintain the template’s existing font and weight tendencies

## Component Usage Rules
- Reuse existing components wherever possible instead of creating a new pattern
- Keep the structure consistent across projects
- Preserve WOW animations and hover behavior
- Use inline styles only for values that must remain dynamic such as state or spacing tweaks
- Prefer reusable blocks over one-off custom sections

## Content Rules
- Write in a way that communicates engineering depth without sounding overly verbose
- Emphasize outcomes, architecture, and system thinking
- Keep case-study content focused on the story behind the build

## Responsive Behavior Rules
- All layouts should remain mobile-friendly
- Cards should stack cleanly on smaller screens
- Visual sections should preserve hierarchy rather than collapsing into text-heavy blocks
- Avoid layout shifts that break the template experience
